# 還元原資100万円へのスポンサー販売計画

作成日：2026年11月25日（日本時間）

## 目標と現在地

ユーザーの希望は、スポンサーを増やして、現金・暗号資産への交換に使う原資を約100万円まで貯めること。ここでの目標は、税込売上の累計ではなく、税・実手数料・返金義務に対応する額などを確保した後、還元へ実際に割り当てられる資金100万円とする。

現在のアプリには本番決済との照合や本番原資台帳が接続されていない。このプロジェクトで確認済みの還元原資は0円。これはKASAI SOLUTIONSの銀行口座やStripe口座全体の残高を示すものではない。商品登録・税設定・営業候補の登録だけで原資は増えない。

承認済みの準備条件は、税込5,000円、実際の掲載開始から30日、1回払い・自動更新なし。初回は1枠を提供し、実績と同時掲載能力を確かめながら増やす。決済リンクは未発行、商品は販売保留。税設定は完了し、日本の顧客向けの実際の価格で税抜4,545円・消費税455円を確認済み。

## 必要契約件数の計算

国内カード決済、日本での標準税率10%、Stripeの標準料金を仮定する。カード手数料3.6%、Payment Links等のTax Basic手数料0.5%、両手数料への消費税10%を計画上確保する。実際の契約プランや支払い方法が異なる場合は実明細に置き換える。

| 5,000円の掲載契約1件 | 計画上の金額 |
| --- | ---: |
| スポンサーの支払総額 | 5,000円 |
| 売上に含まれる消費税の確保 | −455円 |
| 国内カード手数料とその消費税 | −198円 |
| Stripe Tax手数料とその消費税 | −28円 |
| 配分の対象になる額 | 4,319円 |
| その50%を還元原資へ配分 | **2,159円** |

50%は既存の事業計画にある仮の配分率。ユーザーの売上を自動的に配分する設定ではない。画面上で単価や配分率を変えても、Stripeの価格、徴収設定、実際の資金配分は変更されない。

端数は原資を大きく見積もらないよう、控除額を1円単位で切り上げ、還元配分額を切り捨てる。Tax手数料に対する消費税3円はこの予算上の切り上げ額であり、Stripeの最終請求額を予告するものではない。実際の手数料消費税は月次請求書全体で端数処理される。仕入税額控除などで税負担が減る可能性を先取りせず、売上に含まれる消費税を全額確保する。

| 累計の入金・掲載履行済み契約 | 税込売上 | 50%配分の還元原資 |
| ---: | ---: | ---: |
| 10件 | 50,000円 | 21,590円 |
| 50件 | 250,000円 | 107,950円 |
| 100件 | 500,000円 | 215,900円 |
| 200件 | 1,000,000円 | 431,800円 |
| **464件** | **2,320,000円** | **1,001,776円** |

件数は同時掲載数やスポンサーの社数ではなく、履行した30日間の契約数。同じスポンサーの再購入は個別の追加契約として数える。承認済みの商品に自動更新は含まれない。

この計算には追加の制作・外注費、所得に対する税の個別計算、将来の銀行・暗号資産への送金費用は含めていない。実運営で必要額を確保し、資金不足になる場合は配分額や必要契約数を再計算する。還元を始めた後の支払いも、残っている原資から差し引く。100万円は一度売上が積み上がれば維持され続ける残高ではない。

## 比較できる条件

| 税込単価 | 50%の還元原資／契約 | 100万円に必要な契約 | 税込売上 |
| ---: | ---: | ---: | ---: |
| 5,000円（現行） | 2,159円 | 464件 | 2,320,000円 |
| 30,000円（比較試算） | 12,959円 | 78件 | 2,340,000円 |
| 100,000円（比較試算） | 43,199円 | 24件 | 2,400,000円 |

30,000円・100,000円は単価が変わる場合の計算例。新しい商品として登録・販売していない。掲載期間、位置、同時掲載数、紹介内容、提供できる実績資料など、支払う理由になる価値を定義し、買い手の判断を得てから検討する。利用者数や広告実績を確認できていないため、価格を上げただけで売れるとは仮定しない。

現行5,000円で配分を100%とした場合の比較は、1契約4,319円、232契約・売上116万円で1,002,008円。運営費・次の募集費・返金予備費を他の資金から賄う必要があり、100%への変更を実行したものではない。

## スポンサーを増やす手順

### 最初の掲載実績を作る

掲載相談・取消・返金の公開窓口は、ユーザーが指定した [hisashi0128.k@gmail.com](mailto:hisashi0128.k@gmail.com) に設定済み。対象の利用者が閲覧できる掲載場所を用意し、正式な販売者情報と開始・取消・返金条件を確定する。受注、掲載内容の審査、決済確認、掲載、終了、返金の担当と手順を決め、初回の1枠を完了できる状態にする。

営業候補は、まず運営者と接点のある取引先や、新しい媒体への小額の試験出稿を検討できる事業者から整理する。既存の顧客や提携先がいると断定せず、実際の候補だけを登録する。候補ごとに「紹介するサービスが利用者にどう役立つか」「どの掲載内容を実際に提供できるか」を記録する。

### 累計10契約で提案を改善する

最初の提案には、掲載画面、5,000円・30日という条件、ポイント獲得目的の閲覧を含むこと、表示・クリック・売上を保証しないことを記す。まだ未検証の利用者数や反応率は記載しない。

掲載を提供できたら、開始・終了日時と実際の掲載URLを記録する。表示時間を示す場合は取得条件も明記し、人が注視した時間や広告成果と読み替えない。再掲載の希望、出稿を見送った理由、内容への要望を候補メモに残して次の提案に使う。

### 累計50、100契約へ増やす

同時に掲載できる枠の数、表示位置、ローテーションの有無、1件あたりの期間を決め、提供可能な枠だけを販売する。売れた枠を無制限に重ねて掲載価値を下げない。営業候補数、実際の成約、掲載完了、再購入を別々に把握する。

契約や掲載の実績が得られた後、再購入と新規の募集を組み合わせて累計464契約を目指す。現時点では実績に基づく成約率も営業期間もないため、達成日や成約率は保証しない。

## 営業候補管理の意味

アプリの `/sponsor/growth` では次の項目を手動で保存する。

- 企業名・屋号
- 公式サイトのhttps URL（任意）
- 予定する掲載料（税込）
- 候補、提案準備、連絡済、商談中、合意、見送りの段階
- メモ

これは本番の業務メモであり、架空データを自動投入しない。アカウントごとに記録を分離し、編集時のバージョンが古ければ競合として再確認を求める。アーカイブした候補と見送りの候補は有効な見込み合計から除外する。

「連絡済」「合意」は運営者が記録する段階で、送信履歴の自動照合、契約成立の検証、入金証明ではない。予定金額の合計や合意件数を、売上・Stripe利用可能残高・還元原資として扱わない。アーカイブは営業リストから外す操作であり、外部の契約を取消さない。

この画面はメッセージを送信しない。実際の外部営業は、宛先、内容、送信範囲が確認・承認された後に行う。

## 原資を確定する時点

初期運用は、入金確認、30日間の掲載履行、税と実手数料の照合、返金等の留保、還元への資金割当の順に確認する。掲載未提供分を返金できる状態を保ち、入金直後には還元原資へ入れない。

掲載開始前に5,000円全額を返金する場合、Stripeの元の決済処理手数料が返ってくるとは仮定しない。控除された手数料分も運転資金で補填できるようにする。掲載完了後も異議申立てなどに備える予備費は別に残す。同じ資金を未提供の返金引当、予備費、還元原資へ重複計上しない。

本番台帳を実装する際は、注文とStripeの支払いを一意に結び付け、署名検証したWebhook、遅延支払い、返金・異議申立て、照合、提供期間を扱う。現在はこの照合機能がないため、営業候補管理の操作から本番原資へ進捗を加算する経路を設けない。
